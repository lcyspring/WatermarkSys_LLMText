## 摘要

大语言模型生成文本的规模化传播带来了内容溯源难题。本文设计并实现了一套基于 KGW 绿名单的文本水印嵌入与鲁棒检测系统，覆盖生成、嵌入、检测、批量扰动、指标评估与可视化六个环节。
系统在解码阶段以 HMAC-SHA256 派生的伪随机绿名单对 logits 施加偏置 δ，检测端统计有效 token 的绿名单命中数并计算 z 统计量与单侧 p 值；阈值仅由独立负例集合校准，目标误报率 1%，三个偏置档共用同一阈值，避免“按结果调阈值”。
在 60 条提示、4 档 δ、1,080 个后处理变体上完成实验：δ=1 与 δ=2 的检出率均为 100%，AUC 为 1.0000；δ=0.5 的检出率为 71.67%，AUC 为 0.9878；400 条负例校准得到阈值 z ≥ 2.7761，校准集误报率 3/400 = 0.75%（Wilson 95% 置信区间 [0.26%, 2.18%]）。鲁棒性方面，删词 10%/20%/30% 的检出率分别为 95.00%/70.83%/36.67%，截断至 75%/50%/25% 为 100%/99.17%/89.17%，随机替换 10%/20%/30% 为 96.67%/65.00%/23.33%。使用错误密钥检测时平均 z 降至 −0.253，验证了密钥特异性。
本文进一步在真实模型 Qwen2.5-0.5B-Instruct（词表 151,936）上完成 240 条实验（四档 δ 各 60 条）：δ=0 真实负例**全部未误报**（平均 z = −0.07，最大 1.807 < 阈值 2.776，误报率 95% 置信上界 6.02%）；δ=0.5/1/2 的检出率分别为 25.0%/73.3%/100%，平均 z 分别为 1.72/3.75/8.58，单调上升。真实模型 z 明显低于离线预演（δ=2：8.58 对 15.09），说明预演数字偏乐观，本文以真实模型结果为准。真实误报率尚未精确到 1% 以内（需 ≥400 条真实负例）。
本文明确结论边界：系统只回答“是否检出指定算法、配置与密钥的水印证据”，未检出不等于人类撰写，检出也不代表内容真实。

**关键词**：大语言模型；文本水印；绿名单；假设检验；鲁棒检测；可复现实验

## 第 1 章 绪论

### 1.1 研究背景

大语言模型已能稳定生成流畅、连贯的长文本，随之而来的是代写作弊、批量虚假内容、机器生成内容难以溯源等问题。仅依靠文本风格或统计特征判别“是否机器生成”缺乏可验证性：判定规则不透明、易被改写规避、无法追溯责任主体。文本水印提供了一条不同的路径——在生成阶段主动嵌入可被统计检验识别的信号，使“这段文本是否由某个已知模型、在某个已知配置下生成”成为一个可复现的假设检验问题。

### 1.2 研究意义

理论层面，水印把“来源归属”转化为“统计证据强度”问题，衡量指标（误报率、漏报率、统计功效、鲁棒性）都可量化。
工程层面，一个可复现的系统必须同时具备：参数冻结、配置血缘、状态机、批量实验与报告生成。本文的主要工作量正落在这一工程闭环上。

### 1.3 国内外研究现状

Kirchenbauer 等人提出的绿名单水印（KGW）是当前应用最广的方案：在每一步解码时用伪随机函数把词表划分为绿名单与红名单，对绿名单 token 的 logits 加偏置，检测端统计命中比例并做假设检验。其优点是实现简单、可解释、无需额外模型；缺点是面对改写、回译、删词等扰动时信号会衰减，且需要密钥与配置一致才能检测。
后续研究沿三条路线扩展：语义级水印（在句子或语义单元上嵌入信号，抗改写更强但实现复杂）、多比特水印（在文本中编码结构化信息）、无密钥/公开可验证水印（解决密钥分发问题）。本文选择 KGW 作为基线，原因是其数学形式清晰、便于严格校准阈值，适合作为本科阶段的完整工程实践对象。

### 1.4 本文工作

1. 实现 KGW 绿名单水印的完整链路，包括绿名单划分、logits 偏置、检测统计量与状态机；
2. 建立“仅用负例校准阈值”的评估口径，并给出误报率的置信区间；
3. 构建 1,080 个后处理变体的鲁棒性实验，量化三类扰动下的检测衰减；
4. 提供配置血缘（`config_hash`）、SQLite 记录与一键复现脚本；
5. 在真实模型上完成验证：tiny-gpt2 验证链路，Qwen2.5-0.5B 完成 32 条实验，证实“无水印不误报、偏置单调有效”，并量化了真实模型与离线预演的差距。

## 第 2 章 相关理论与技术基础

### 2.1 自回归生成与采样

语言模型在每一步对词表输出 logits，经温度缩放与 softmax 得到分布后采样：

```
p_i = softmax(logits_i / T)
```

温度 T 越低，分布越尖锐、输出越确定；T 越高，采样越随机。水印的偏置直接作用于 logits，因此在低温度下（分布本身很尖）偏置更难改变采样结果，检测信号会减弱。第 5.6 节的温度实验印证了这一点。

### 2.2 绿名单水印原理

设词表大小为 V，绿名单比例 γ，上下文宽度 h。对位置 t，以密钥 K 与前 h 个 token 为输入，用 HMAC-SHA256 派生随机种子，再由该种子从词表中抽取 ⌊γV⌋ 个 token 构成绿名单 G_t：

```
seed_t = HMAC-SHA256(K, "kgw-v1" || h || token_{t-h} || ... || token_{t-1})
G_t    = Sample(seed_t, ⌊γV⌋)
```

生成时对绿名单 token 的 logits 加 δ。若无水印（δ=0），每个生成 token 落入绿名单的概率为 γ；若有水印，该概率上升。检测端统计 n 个有效位置中命中绿名单的个数 g，构造 z 统计量：

```
z = (g − γn) / sqrt(n·γ(1−γ))
```

在无水的零假设下 z 近似服从标准正态分布，故单侧 p 值为 `p = 0.5·erfc(z/√2)`。

### 2.3 假设检验与阈值

给定目标误报率 α（本文取 1%），阈值 τ 应满足“负例被误判为有水印的比例不超过 α”。本文只使用独立负例集合确定 τ：取负例 z 分数的 1−α 分位数，并向上取整到 10⁻⁶，保证实测误报率不超过目标值。三个 δ 档共用同一 τ，杜绝按结果调参。

需要强调的是：400 条负例下零误报的置信区间上界仍约为 0.9%，因此“零误报”不能等同于“总体误报率为 0”；论文报告误报率时必须同时给出置信区间。

### 2.4 评估指标

以“含水印文本”为正类，定义 TP/FP/TN/FN，进而计算准确率、精确率、召回率、F1、误报率 FPR、漏报率 FNR，以及不依赖阈值的 AUC 与指定误报率下的召回率 TPR@FPR。对长文本与短文本分别统计，可观察统计功效随有效长度 n 的变化。

## 第 3 章 系统需求与总体设计

### 3.1 功能需求

| 编号 | 需求 | 验收口径 |
|---|---|---|
| F1 | 按提示批量生成文本 | 每条记录含 config_hash、delta、token_ids、状态 |
| F2 | 嵌入水印 | δ=0 时不修改任何 logits |
| F3 | 检测 | 输出 n、g、z、p、判定与状态 |
| F4 | 阈值校准 | 仅用负例，报告经验误报率与置信区间 |
| F5 | 批量后处理 | 删词/截断/替换，记录实际扰动强度 |
| F6 | 指标与报告 | 主结果表、分层表、鲁棒性表自动生成 |
| F7 | 可视化 | 网页仪表盘与检测接口 |

### 3.2 非功能需求

**可复现**：所有参数进入 `WatermarkConfig`，其 SHA-256 短哈希作为 `config_hash`；任一参数变化必须改变哈希。
**可追溯**：生成、检测、编辑、指标四类记录写入 SQLite。
**可降级**：核心算法不依赖 torch；真实模型与离线模拟共用同一检测口径。

### 3.3 总体架构

系统分为五层：生成层（真实模型适配器 / 离线机制模拟器）、水印嵌入层、检测层、后处理层、评估与展示层。数据以 JSONL 为主、SQLite 为辅；报告由脚本从数据自动生成，避免手工誊抄数字。

### 3.4 状态机

检测结果必须显式区分状态：`completed`（有效长度足够）、`insufficient_length`（有效 n < 32）、`failed`（计算异常）、`config_mismatch`（配置不一致）。这一设计避免了“把不足长度的样本当作未检出”的口径错误。

## 第 4 章 水印嵌入与检测的实现

### 4.1 绿名单划分

实现上采用拒绝采样：由 HMAC 派生种子后，反复抽取随机 token 直到得到 ⌊γV⌋ 个互不相同的 id。相比“生成全词表置换再取前 k 个”的写法，复杂度从 O(V) 降到 O(γV)，使数万次批量检测成为可能（实测单次划分约 0.18 ms，2,048 词表）。

### 4.2 生成端偏置

`KGWLogitsProcessor` 在每一步解码读取上下文、重建绿名单并给对应 logits 加 δ。**当 δ=0 时函数直接返回原 logits**，不做任何加法与张量操作，确保基线完全不受水印代码影响。该行为由单元测试断言。

### 4.3 检测端实现

检测按以下规则确定有效位置：排除提示前缀（提示不是模型生成）、排除特殊 token、屏蔽会构成重复 n-gram 的位置。第三条尤其重要：若模型自我复读，同一片段会被反复计入 n 与 g，造成 z 虚高。第 5.6 节的消融实验显示，对一段 240 token 的复读文本，不屏蔽时 z = 26.83，屏蔽后有效 n 从 240 降到 1，虚高信号被消除。

### 4.4 阈值校准实现

校准脚本生成 400 条 δ=0 负例（40 条提示 × 10 个随机种子），逐条检测取 z，按 1% 目标取分位数并向上取整，同时用 Wilson 方法计算误报率的 95% 置信区间。

### 4.5 关键工程决策

| 决策 | 理由 |
|---|---|
| δ=0 直通而非加 0 | 避免浮点运算与随机性污染基线 |
| 排除提示前缀 | 提示不是模型生成内容，计入会稀释信号 |
| 屏蔽重复 n-gram | 防止复读造成 z 虚高 |
| 阈值向上取整 | 保证实测误报率不超过目标 |
| 三档共用阈值 | 杜绝按结果调参 |
| 配置指纹与哈希分离 | 指纹表征算法身份，哈希覆盖全部实验变量 |

## 第 5 章 实验设计与结果分析

### 5.1 实验设置

提示集 60 条，覆盖学术、技术、新闻、问答四类任务与中英两种语言，其中 40 条用于校准、20 条用于测试。固定参数 γ = 0.25、h = 4、PRF = HMAC-SHA256、ngram_block = 4，最小有效长度 32 token。生成长度 200 token，δ ∈ {0, 0.5, 1, 2}。
**运行模式说明**：主实验使用机制级离线模拟器（词表 2,048），其采样过程与 KGW 偏置机制完全一致，用于验证流水线与统计口径；真实模型链路另用 tiny-gpt2 单独验证（第 5.7 节）。这一区分在全部报告中均有标注。

### 5.2 阈值校准

| 项目 | 数值 |
|---|---|
| 负例数 | 400 |
| 目标误报率 | 1% |
| 选定阈值 | z ≥ 2.7761 |
| 校准集误报 | 3/400 = 0.75% |
| Wilson 95% CI | [0.26%, 2.18%] |

### 5.3 主结果

| δ | 平均 z | 检出率 | 漏报率 | AUC |
|---|---|---|---|---|
| 0 | 0.12 | 0.00% | — | — |
| 0.5 | 3.503 | 71.67% | 28.33% | 0.9878 |
| 1.0 | 7.234 | 100.00% | 0.00% | 1.0000 |
| 2.0 | 15.086 | 100.00% | 0.00% | 1.0000 |

δ 增大时平均 z 与检出率单调上升，说明偏置方向正确、统计量有效。δ=0.5 是“可用但非鲁棒”的临界档，其漏报率 28.33% 主要来自有效长度较短的样本。

### 5.4 长度分层

按有效长度分箱后，短文本（32–63 token）检出率最低。这与统计功效随 n 增长的理论一致：z 的期望随 √n 增长，短文本在同等偏置下更难达到阈值。工程含义是：检测结果必须报告有效长度，长度不足时应返回 `insufficient_length` 而不是“未检出”。

### 5.5 鲁棒性

对 δ ∈ {1, 2} 的 120 条源文本施加三类扰动，共 1,080 个变体：

| 扰动 | 档位 | 平均有效 n | 平均 z | 检出率 |
|---|---|---|---|---|
| 删词 | 10% | 180.0 | 6.828 | 95.00% |
| 删词 | 20% | 160.0 | 4.172 | 70.83% |
| 删词 | 30% | 140.0 | 2.334 | 36.67% |
| 截断 | 75% | 150.0 | 9.606 | 100.00% |
| 截断 | 50% | 100.0 | 7.827 | 99.17% |
| 截断 | 25% | 50.0 | 5.617 | 89.17% |
| 替换 | 10% | 200.0 | 6.645 | 96.67% |
| 替换 | 20% | 200.0 | 3.689 | 65.00% |
| 替换 | 30% | 200.0 | 1.943 | 23.33% |

两点观察：其一，截断虽然减少 n，但保留了前缀中连续的有效位置，因此比同比例的随机删词更“友好”；其二，替换不改变长度却直接破坏 n-gram 上下文，使后续位置的绿名单重建失配，衰减最快。这说明水印对“局部随机改写”最脆弱，与 KGW 的已知局限一致。

### 5.6 压力与一致性

| 测试 | 结果 | 含义 |
|---|---|---|
| 正确密钥 | 平均 z = 14.811 | 正常检出 |
| 错误密钥 | 平均 z = −0.253 | 密钥特异性成立，无密钥者读不出水印 |
| γ = 0.20 / 0.25 / 0.30 | 12.719 / 14.811 / 13.131 | γ 必须与生成端一致 |
| 温度 0.7 / 1.0 / 1.3 | 19.563 / 14.811 / 11.921 | 温度越高，偏置越难改变采样 |
| 复读文本（不屏蔽） | z = 26.833，n = 240 | 虚高，会把复读误判为水印 |
| 复读文本（屏蔽） | z = 1.732，n = 1，屏蔽 239 位 | 有效位置不足，不应给出判定 |

配置一致性方面，δ、γ、h、算法版本、密钥标识任一变化都会改变 `config_hash`，保证任何图表数字都能回溯到唯一配置。

### 5.7 真实模型实验

主实验使用机制级模拟，只能证明算法与流水线正确。为此补充两组真实权重实验。

**（1）链路验证：tiny-gpt2（真实 50,257 词表）**

| δ | 样本数 | 平均 z | 检出 |
|---|---|---|---|
| 0 | 6 | −0.29 | 0/6 |
| 2 | 6 | 13.86 | 6/6 |

该结果证明真实 tokenizer、真实 logits 与 `KGWLogitsProcessor` 的配合正确。tiny-gpt2 输出无语义，此实验只作链路验证。

**（2）主模型实验：Qwen2.5-0.5B-Instruct（词表 151,936，CPU 推理）**

8 条提示 × 4 档 δ × 128 token，共 32 条，平均 9.47 秒/条：

| δ | 平均 z | z 最小 | z 最大 | 判为有水印 |
|---|---|---|---|---|
| 0 | 0.389 | −0.564 | 1.429 | 0/8 |
| 0.5 | 1.774 | −0.612 | 3.470 | 2/8 |
| 1.0 | 4.116 | 2.041 | 5.920 | 7/8 |
| 2.0 | 10.283 | 8.981 | 11.839 | 8/8 |

三点发现：其一，δ=0 的最大 z 仅 1.429，低于阈值 2.776，真实模型上未出现误报；其二，平均 z 随 δ 严格单调上升，δ=2 时最小 z 仍达 8.981；其三，**真实模型各档 z 均低于离线预演**（如 δ=2：10.283 对 15.086），主要因为真实词表大 74 倍、绿名单绝对数量更多，且真实采样包含标点、特殊 token 与语言切换。这说明离线预演数字偏乐观，论文应以真实模型结果为准。

需明确局限：每档仅 8 条，且阈值沿用离线校准（零假设下 z 与词表大小无关，跨词表使用在统计上成立）。

**（3）扩样实验：四档各 60 条（共 240 条）**

在 60 条提示上对 δ∈{0,0.5,1,2} 各生成 1 条（128 token）：

| δ | 样本 | 平均 z | 检出 | Wilson 95% CI |
|---|---|---|---|---|
| 0 | 60 | −0.07 | 0/60 | 误报率 [0%, 6.02%] |
| 0.5 | 60 | 1.72 | 15/60（25.0%） | — |
| 1.0 | 60 | 3.75 | 44/60（73.3%） | — |
| 2.0 | 60 | 8.58 | 60/60 | 检出率 [93.98%, 100%] |

扩样后 δ=2 的平均 z 由 10.283 降至 8.577，δ=1 由 4.116 降至 3.75，说明 8 条小样本存在向上的偶然偏差。δ=0 的 60 条中最大 z 仅 1.807，未触及阈值。**真实负例仍不足 400 条，真实误报率尚未精确估计**。

### 5.8 质量影响

四档 δ 的 distinct-1 均约 0.952、repeat-4 均为 0、压缩比约 2.37，表层统计特性无显著差异。语义质量需 BERTScore 与人工盲评，其中盲评材料（120 对）已生成，评分尚未完成。

### 5.9 实验规模与限制

已完成真实模型小规模实验（32 条）与链路验证（12 条），但以下规模化工作尚未完成，列为后续：

1. 真实负例重校准：需 Qwen 生成 ≥400 条 δ=0 文本，重新确定阈值并报告 Wilson 区间；
2. 扩大每档样本量至 40 条以上，使检出率具备统计意义；
3. 在真实模型输出上重做 1,080 变体的鲁棒性实验（当前基于离线文本）。

当前环境为 CPU 推理（`cuda.is_available()` 为 False），单条 128 token 约 9.47 秒，规模化实验耗时是主要瓶颈；模型权重已本地化，复现命令见第 6.4 节。

## 第 6 章 系统实现与展示

### 6.1 技术栈

Python 3.11、NumPy、PyTorch（可选）、Transformers（可选）、FastAPI、Jinja2、SQLite。

### 6.2 模块划分

`src/wm` 下分为 `watermark`（算法）、`detect`（检测与校准）、`postprocess`（扰动）、`eval`（指标与质量）、`pipeline`（流水线）、`db`（血缘）、`web`（展示）。`scripts` 提供 00–13 号脚本，`12_run_all.py` 一键复现全部实验，实测约 70 秒。

### 6.3 Web 演示

仪表盘展示阈值与各 δ 档指标；`POST /api/generate` 生成并即时检测；`POST /api/detect` 对给定 token 序列检测。接口经自动化测试覆盖。

### 6.4 真实模型复现路径

```
# 1) 换 CUDA 版 PyTorch（RTX 4060 8GB 足够）
pip install torch --index-url https://download.pytorch.org/whl/cu128

# 2) 用 ModelScope 下载模型（国内速度明显优于 hf-mirror）
modelscope download --model Qwen/Qwen2.5-0.5B-Instruct --local_dir D:\models\Qwen2.5-0.5B-Instruct

# 3) 生成与检测（--vocab 必须等于真实词表 151936）
python scripts/04_generate.py --mode hf --model-id D:\models\Qwen2.5-0.5B-Instruct `
       --deltas 0,0.5,1,2 --limit 20 --max-new-tokens 128 --vocab 151936 --out outputs/hf_qwen.jsonl --fresh
python scripts/06_detect.py --input outputs/hf_qwen.jsonl --vocab 151936
```

48 项单元测试覆盖绿名单确定性、z 公式、δ=0 直通、重复屏蔽、提示前缀排除、阈值校准、AUC/TPR、长度分层、后处理实际强度、数据库读写、配置哈希与 Web 接口。

## 第 7 章 总结与展望

### 7.1 工作总结

1. 实现了 KGW 水印的完整链路，并以“δ=0 直通”保证基线纯净；
2. 建立了仅用负例校准、报告置信区间的评估口径；
3. 完成 1,080 个变体的鲁棒性度量，量化了删词、截断、替换的衰减规律；
4. 验证了密钥特异性与配置一致性；
5. 用真实权重验证了真实模型链路，并如实披露主模型实验的未完成原因。

### 7.2 局限

真实实验样本量有限（每档 8 条），真实负例不足 400 条，真实误报率尚未估计；鲁棒性实验基于离线文本，尚未在真实模型输出上重做；语义质量与人工盲评未完成；未覆盖回译与语义改写等强攻击。

### 7.3 展望

在 GPU 环境完成主模型规模化实验；引入语义水印与多比特水印；研究针对随机替换的鲁棒增强（如上下文冗余编码）；探索公开可验证方案以缓解密钥分发问题。
